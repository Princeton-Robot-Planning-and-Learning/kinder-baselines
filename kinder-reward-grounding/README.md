# kinder-reward-grounding

Early prototype for modular reward grounding in KinDER-style MPC and
trajectory optimization.

The project converts a structured task specification into an
MPC-compatible reward function:

```text
task / language goal
    -> subgoal specification
    -> predicate library
    -> progress score
    -> composite reward
    -> trajectory scoring / MPC
```

## Overview

`kinder-reward-grounding` separates task semantics from planner mechanics.
Instead of writing one monolithic reward function per environment, a task is
represented as a `RewardSpec` containing objects, subgoals, predicates,
progress metrics, and reward-composition settings.

The evaluator then binds that specification to an environment adapter and
returns a scalar reward function suitable for trajectory optimization or MPC.

## Current status

This repository is an early-stage prototype. It currently validates the reward
grounding interface using **hand-crafted** oracle subgoals and predicates
over object-centric KinDER state.

Important limitation: current subgoals are not generated by a real VLM. The
`VLMGrounder` interface is only a placeholder boundary, and `MockVLMGrounder`
exists so tests can exercise VLM-shaped code without GPU or server access.

## Repository structure

```text
kinder-reward-grounding/
  docs/                         Design notes and roadmap
  examples/                     Runnable 2D demo scripts
  src/kinder_reward_grounding/
    adapters/                   Environment adapters, including KinDER state decoding
    env_specs/                  Hand-crafted reward specs for current demos
    grounders/                  VLM placeholder interface and deterministic mock
    library/                    Public spec-factory entrypoints
    predicates/                 Predicate registry and predicate functions
    rewards/                    Progress metrics, reward composers, evaluator
    utils/                      Geometry helpers
  tests/                        Unit tests for specs, predicates, rewards, grounders
```

## Quick start

From this package directory:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
pytest
```

## Minimal 2D example

To run the current 2D MPC sanity demo:

```bash
python examples/motion2d_spec_reward_mpc.py
python examples/dyn_pushpullhook2d_spec_reward_mpc.py
```

It saves a GIF under `outputs/` and prints distance/progress diagnostics.

## Trajopt-compatible evaluation logs

To produce `config.yaml` and `results.csv` files compatible with the existing
`kinder-trajopt` analyzer, run the reward-grounding evaluation runner:

```bash
python experiments/run_reward_grounding_eval.py \
  --env dynpushpullhook2d-o0 \
  --method spec_reward \
  --seeds 0-2 \
  --num-eval-episodes 50 \
  --output-dir outputs/reward_grounding_smoke/DynPushPullHook2D-o0-v0_spec_reward \
  --no-gifs \
  --max-steps 200
```

This creates numbered seed/job directories:

```text
outputs/reward_grounding_smoke/DynPushPullHook2D-o0-v0_spec_reward/
  0/config.yaml
  0/results.csv
  1/config.yaml
  1/results.csv
  2/config.yaml
  2/results.csv
```

Then run the official trajopt analyzer:

```bash
python ../kinder-trajopt/experiments/analyze_results.py \
  outputs/reward_grounding_smoke/DynPushPullHook2D-o0-v0_spec_reward
```

The current 2D evaluation has been smoke-tested on
`kinder/DynPushPullHook2D-o0-v0` with 3 seeds and 50 episodes per seed. One
prototype run produced:

```bash

Solve Rate: 26.7% ± 11.5%
Planning Time: 864.81 ± 70.74 s
Execution Time: 0.2436 ± 0.0161 s
Average Steps: 188.7

```

## Current scope

- Hand-crafted `RewardSpec` objects for 2D KinDER environments.
- Oracle object-state predicates such as `near`, `held`, and
  `vertical_gap_below`.
- Dense progress metrics based on object distance, keypoints, and vertical gap.
- Sequential reward composition for MPC-style trajectory scoring.
- Placeholder VLM interface only; no real VLM inference.

## Next steps

- Connect a real VLM-backed grounding implementation behind `VLMGrounder`.
- Test whether the same reward-spec interface is feasible in 3D KinDER tasks.
- Evaluate 3D + VLM reward grounding once 3D state/scene interfaces are clear.

## Known limitations

- The current subgoal decomposition is manually written and oracle-style.
- Real VLM inference, prompting, parsing, and calibration are not implemented.
- The main target is still 2D; 3D geometry and scene grounding are planned.
- Reward scales are prototype values and may need tuning per environment.
- Some geometry helpers are heuristic, especially for tool keypoints.
